Apply cấu hình Terraform

Khởi tạo một EC2 instance và một S3 bucket, quan sát cách Terraform xử lý lỗi trong lúc apply, và thực hành các cách dùng phổ biến của lệnh apply.

Quy trình cốt lõi của Terraform gồm ba bước, sau khi bạn đã viết cấu hình:

  • 01
    InitializeChuẩn bị workspace để Terraform có thể áp dụng cấu hình của bạn.
  • 02
    PlanXem trước những thay đổi mà Terraform sẽ thực hiện trước khi apply.
  • 03
    ApplyThực thi các thay đổi trong plan để tạo, cập nhật hoặc xoá tài nguyên.

Yêu cầu chuẩn bị

Bạn có thể hoàn thành tutorial này với Terraform Community Edition hoặc HCP Terraform — nền tảng quản lý và thực thi các dự án Terraform, bao gồm remote state, remote execution và các tóm tắt tài nguyên theo workspace.

Community Edition HCP Terraform

Bạn sẽ cần:

  • Terraform v1.6 trở lên, đã cài đặt cục bộ.
  • Một tài khoản AWS với credentials đã cấu hình cho Terraform.
  • Công cụ dòng lệnh jq.

Xem lại cấu hình

Repository mẫu tạo một EC2 instance và một S3 bucket. Sau khi clone về, cấu trúc thư mục gồm các file cấu hình chính sau:

main.tf
resource "aws_instance" "main" {
  count         = 3
  ami           = data.aws_ami.ubuntu.id
  instance_type = "t2.micro"

  tags = {
    Name  = "${random_pet.instance.id}-${count.index}"
    Owner = "${var.project_name}-tutorial"
  }
}

resource "aws_s3_bucket" "example" {
  tags = {
    Name  = "Example Bucket"
    Owner = "${var.project_name}-tutorial"
  }
}

Tài nguyên aws_instance.main phụ thuộc vào random_pet.instance và data source aws_ami.ubuntu. Vì aws_s3_bucket.example không phụ thuộc tài nguyên nào khác, Terraform sẽ tạo nó song song với các tài nguyên còn lại.

Khởi tạo cấu hình

Trước khi tạo execution plan, Terraform cần cài đặt mọi provider và module mà cấu hình tham chiếu tới.

terminal
$ terraform init
Initializing provider plugins...
- Installing hashicorp/aws v6.2.0...
- Installed hashicorp/aws v6.2.0 (signed by HashiCorp)
- Installing hashicorp/random v3.5.1...
- Installed hashicorp/random v3.5.1 (signed by HashiCorp)

Terraform has been successfully initialized!

Apply cấu hình

Chạy lệnh apply. Vì bạn chưa cung cấp saved plan, Terraform sẽ tự tạo một plan và yêu cầu bạn xác nhận trước khi thay đổi bất kỳ tài nguyên nào.

Khi bạn chấp thuận plan, Terraform sẽ: khoá state của workspace, thực thi các bước trong plan bằng provider đã cài đặt (song song khi có thể, tuần tự khi tài nguyên phụ thuộc lẫn nhau), cập nhật state, mở khoá state, rồi báo cáo kết quả cùng các output value.

terminal
$ terraform apply
Plan: 5 to add, 0 to change, 0 to destroy.

  Enter a value: yes

random_pet.instance: Creation complete after 0s [id=dashing-tapir]
aws_s3_bucket.example: Creation complete after 2s
aws_instance.main[0]: Creation complete after 53s
aws_instance.main[1]: Creation complete after 43s
aws_instance.main[2]: Creation complete after 33s

Apply complete! Resources: 5 added, 0 changed, 0 destroyed.

Lỗi phát sinh khi apply

Khi Terraform gặp lỗi trong bước apply, nó sẽ: ghi log và báo lỗi ra console, cập nhật state file với những thay đổi đã kịp thực hiện, mở khoá state, rồi thoát. Terraform không tự động rollback một apply dở dang — bạn cần apply lại sau khi khắc phục nguyên nhân.

Lưu ý — Hạ tầng của bạn có thể ở trạng thái không hợp lệ sau khi một bước apply lỗi. Hãy chạy lại terraform apply sau khi xử lý xong nguyên nhân gốc.

Một số nguyên nhân phổ biến gây lỗi khi apply:

  • Tài nguyên bị thay đổi bên ngoài phạm vi kiểm soát của Terraform.
  • Lỗi mạng hoặc các lỗi tạm thời khác.
  • Lỗi có thể lường trước từ API upstream, ví dụ trùng tên tài nguyên hoặc chạm giới hạn.
  • Lỗi không lường trước từ API upstream, ví dụ lỗi máy chủ nội bộ.

Thay thế tài nguyên

Terraform cung cấp hai tham số cho lệnh plan và apply để thao tác với từng tài nguyên riêng lẻ: -replace và -target. Dùng -replac
